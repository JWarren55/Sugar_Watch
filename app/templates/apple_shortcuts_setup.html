Build your free health shortcut

Back to Apple Health

This is a one-time manual build in Apple's Shortcuts app. It is more involved than installing a signed shortcut. Start with Sleep, test it, then duplicate the collector for the other categories. An Apple Health export is the simpler way to import your full history and workouts now.

Before you start

Use your iPhone on Wi-Fi. Keep it unlocked. Have your connection key from the Apple Health page ready. Do not paste it into a shared shortcut or share it with others.

The server addresses below are generated for this Sugar Watch installation. Add a header named Authorization to each Get Contents of URL action. Its value is your complete Bearer … key. Set the request method to POST and Request Body to JSON.

Build “Sugar Watch Sleep”

Open Shortcuts → +, and name the shortcut Sugar Watch Sleep. Add these actions in order. Bold names are actions to search for. Names in code are variables or dictionary keys you create.

  1. Stop unless Wi-Fi is connected

    Add Get Network Details, choose Wi-Fi → Network Name. Add If the name does not have any value, then Stop This Shortcut. End If. Put this before every network or Health action. If Wi-Fi access is denied, stop rather than assuming you are connected.

  2. Ask Sugar Watch which dates it needs

    Add Get Contents of URL using the Request a range address above. Add the Authorization header. In its JSON body add metric as Text = sleep, and on_wifi as Boolean = true.

    Add Set Variable named SyncPlan to keep the response. Use Get Dictionary Value for status. If it is up_to_date, stop this shortcut. Otherwise get start, end, and plan from SyncPlan, keeping each as a variable.

  3. Read the individual sleep records

    Add Find Health Samples. Type = Sleep; Start Date is on or after the returned start date and before the returned end date. Convert the returned ISO dates with Get Dates from Input if the date field needs a date variable. Sort by Start Date, oldest first. Turn Limit off.

    Allow Shortcuts to read Sleep when asked. Do not add a Statistics action or sum the results. Keep the list as Samples. Add Count to get TotalRecords.

  4. Split the list into groups of 200

    Calculate TotalRecords ÷ 200 and use Round Number → Always Round Up → Ones Place to get TotalBatches. If TotalRecords is zero, set TotalBatches to 0 and skip the batch loop.

    Repeat TotalBatches times. For each Repeat Index, calculate first position = (Repeat Index - 1) × 200 + 1. Last position = the smaller of Repeat Index × 200 and TotalRecords. Use Get Item from List → Items in Range on Samples.

  5. Make a dictionary for each sample in that group

    Inside the batch loop, use Repeat with Each sample in the group. Use Get Details of Health Sample to read Start Date, End Date, Value, and Source. Use Format Date → ISO 8601 on both dates so they include a time-zone offset.

    Add a Dictionary with Text keys start, end, value, and source, filling them with those values. Keep sleep Value as text (Core, Deep, REM, Awake, In Bed, or Asleep). The inner Repeat Results must be the list of dictionaries for this batch. Do not turn that list into joined text.

  6. Upload this batch, then move to the next

    After the inner repeat, add Get Contents of URL using Send a batch. Add the same Authorization header and a JSON body: plan = the plan text from SyncPlan; index as Number = Repeat Index minus 1; records as Array = the inner Repeat Results. Use the variable containing the list rather than typing JSON text.

    Check the response's status. It must equal ok. Stop on any error. Do not add a retry loop or continue to confirmation after a failed batch.

  7. Confirm only after every batch succeeds

    Outside both repeats, add Get Contents of URL using Confirm a finished range. Add the same header. JSON body: plan = plan text; batches as Number = TotalBatches; records as Number = TotalRecords. This also runs for an empty list with both counts set to 0.

    The response must say ok. Sugar Watch only advances this category's progress when every declared batch is present. If a run fails, stop and run the shortcut later; already-saved samples will not be duplicated.

Health labels can vary by iOS language and version. Find the matching category rather than choosing a similarly named measurement. Workouts cannot be fully collected with this recipe; update them using Apple's export.zip.

Make one daily button

Create a shortcut named Sugar Watch Sync. Start with the same Wi-Fi check. Add Run Shortcut once for each collector you built. Run this manually while unlocked to approve permissions and check the received data.

For a charging trigger, use Shortcuts → Automation → + → Charger → Is Connected. Choose Run Immediately if offered, then run Sugar Watch Sync. Already-synced categories stop before querying Health. Do not schedule it every few minutes. If the phone was locked, unlock it and tap Sugar Watch Sync later.

What happens if a run is missed?

Apple Health keeps your records. Server progress does not advance on incomplete delivery. Each range covers at most two days with overlap. A long gap can take several runs to catch up; use the native file import to bring in a large history without running many shortcut queries.

Automatic runs are not guaranteed. A Wi-Fi name check cannot prevent a route change after Wi-Fi drops. For a strict no-cellular run, enable Airplane Mode, then turn Wi-Fi back on before running. Raw Health sample lists do not need to be saved to Files. Keep your shortcut private: its saved connection key can sync within your Apple Account if Shortcuts iCloud sync is enabled. Never publish a shortcut containing your key.
